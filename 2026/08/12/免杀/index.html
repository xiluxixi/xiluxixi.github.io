虚拟机检测技术

主要是在高级语言例如c语言中嵌入汇编代码，例如x86 CPUID 指令，程序直接内嵌汇编执行 cpuid，读取寄存器返回的厂商字符串、虚拟化标志位，判断是否处于虚拟机

分为两大检测维度：CPU Vendor 厂商签名检测、CPU Feature 虚拟化特性位检测。

CPUID 指令工作逻辑

cpuid 靠输入 EAX=功能号 区分查询内容，输出信息存 EBX/ECX/EDX：

  1. EAX=0：读取 CPU 基础厂商字符串（物理 CPU / 虚拟机 VMM 签名）
  2. EAX=1：读取基础 CPU 特性位（含硬件虚拟化 VMX/SVM）
  3. EAX=0x40000000：Hypervisor 专属叶，虚拟机专属厂商标识（最精准检测点）
  4. EAX=0x8000000A：AMD 扩展 SVM 虚拟化标志

CPUID 返回的 ECX/EDX 寄存器每一位代表一个 CPU 硬件特性，虚拟机环境下会出现物理机不会出现的标志位。

  1. Hypervisor Bit（ECX bit 31，EAX=1）
  2. Intel VT-x 标志：VMX Bit（ECX bit5，EAX=1）
  3. AMD SVM 标志：SVM Bit（ECX bit2，EAX=0x8000000A）

反射型dll

首选区分一下正常的dll注入和反射dll的区别：

  1. 正常的dll注入一般是openprocess目标进程，创建一小块内存写入dll的路径，然后使用remoteprocess执行loadlibrary加载dll
  2. 而反射型dll则是往目标进程内存写入一个dll，然后remoteprocess调用dll里面的一个特殊的函数，这个函数会实现类似loadlibrary加载dll的功能，然后会调用dll的dllmain入口，这种手法可以防止edr hook loadlibrary并且可以实现无文件落地，但是无法防住hook remoteprocess，可以试一下 Dirty Vanity或者Pool Party，这两个可以绕过remoteprocess

当然他自己也列了一些常见的跨平台漏洞

  • 内存安全：例如栈溢出，uaf，double free，我就是看到这几个才想着是否有通用的漏洞点，还有变量类型混淆，想起来react的满分cve

  • 序列化和解释器：这种利用逻辑发现规则漏洞的没怎么接触过，但感觉很厉害········吧······
